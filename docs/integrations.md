# 第三方管理台接入

返回 [文档入口](README.md)。本文适用于 CloudPhone、ScrcpyOverWebRTC 适配器或其他通过 PVE 创建 Android CT 的控制面。

## 一套官方运行规则

管理台负责资源与业务；本仓库负责 Android/PVE 运行兼容。不要在管理台维护第二份 `lxc.init.cmd`、设备、GPU、FUSE、DHCP 或 Android 补丁规则。

| 接入方维护 | redroid-pve 维护 |
| --- | --- |
| PVE 连接凭据、节点绑定、任务 UPID | 官方安装器、运行时版本与配置接口 |
| 实例 UUID、资源选择、存储/网桥、配额 | 基础设备、GPU、用户命名空间与启动规则 |
| Agent 二进制、init rc、连接配置 | Android 镜像与 AOSP 兼容补丁 |
| 自有目录/挂载权限、注册、显示名称 | 静态网络准备与 Android DHCP 生命周期 |
| 快照策略、重置恢复、失败记录清理 | 保留快照和无关配置的幂等渲染 |

原生 PVE 用户不安装任何接入方组件，也必须能正常使用官方镜像和运行时。

## 推荐部署与创建顺序

1. 添加目标节点后，核对 PVE API 与 SSH 实际指向同一节点。
2. 在该节点安装固定来源的官方 deploy 文件；另外部署接入方自己的 Agent 资源。安装成功需要实查文件、`--version`，并通过 1.1.1 起提供的 `--check-host --json` 确认 `ready` 与 `binderfs` 为 true，不能只保存一个数据库 ready 标志。缺失时按已有策略调用官方安装器，不在管理台另写 modprobe/内核准备规则。
3. 从节点实际存储读取用户已下载的模板。DHCP 检查运行时至少 1.1.0，并调用 `--check-dhcp` 检查实际模板。
4. 通过 PVE API 创建停止的 CT，设置 CPU/内存/磁盘、实际网桥及静态地址或 `ip=dhcp`。原生便利脚本调用方可使用 `--no-start`。
5. 对已有停止 CT 调用 `pve-configure-redroid`，显式传入希望保留的完整显示、GPU 和设备配置。
6. 增加自己的 Agent/config 挂载，准备对应权限，不删除官方块或其他集成的挂载。
7. 通过 PVE 启动并等待 UPID 成功；再分别核对 Android、实际网络、Agent 注册和画面。

缺少官方命令时，应提示或按既有部署策略准备节点，不能临时生成另一套启动脚本。官方安装器也不包含第三方 Agent，接入方需独立保证资源配套。

## 非特权挂载权限

宿主 root 可读的文件不一定能被非特权 CT 的映射用户查找。挂载源的每一级目录都需要相应搜索权限，配置文件需允许实际运行 Agent 的映射身份读取。

接入方应使用 PVE 提供的实际 ID 映射信息，兼容默认和自定义映射，不能固定假设 root 永远映射为 100000。配置中若含密钥，不应通过全局 `chmod 777` 或公开目录来解决。

CloudPhone 曾因其 `instances/` 目录为 root:root 0750，导致 LXC 在 `cloudphone.conf` bind mount 阶段失败。这是配置生产者的权限问题；应在管理台的配置创建、更新和启动检查中修复，不应加入官方 Android 启动 Hook。

## 身份、名称和多管理台

VMID 在 PVE 集群内分配，但可以在删除后复用，也可在另一集群重复。管理台应保存独立实例身份及绑定，操作前核对真实归属。不能仅凭 VMID 或 API 请求失败就停止、接管或销毁资源。

显示名称和连接身份分别维护。以 CloudPhone 为例，`CP_AGENT_ID` 是其注册/权限/租约标识，显示名称可以单独同步；这些字段与控制面业务策略不属于官方镜像的强制要求。

区分两个操作：删除真实 CT 要确认归属；清理本地失效记录不应删除另一管理台的 CT、共享 Agent 或宿主文件。复制相同控制面元数据可能复制归属身份，不能把这种部署当成已有分布式锁保护。

## DHCP 与状态同步

DHCP 不走静态地址池分配或 ARP 预占，不传静态网关，也不部署宿主 dhclient。创建时地址为空是正常情况；启动后读取 `--network-status`，地址变化更新连接展示，实例身份保持稳定。

API 连通、LXC running、Android boot completed、网络 ready、Agent registered 和画面正常分别展示与验收。PVE 删除 CT、断网、权限失败、迁移和 VMID 复用也应分别处理；不存在配置的 PVE 请求可能返回 HTTP 500，不能把任意 500 当成已删除。

## 固定来源与升级

消费方可以使用本仓库源码或生成固定 deploy 快照，但应保留 LICENSE、上游仓库、提交号、接口/运行时版本及逐文件摘要。消费方生成目录不能作为运行规则的唯一源码。

运行逻辑先在本仓库修改并验证，再提交，最后由消费方同步器生成快照。记录镜像、运行时、Agent 和管理台组合，保留历史验收版本；不要为更新文档而重启现有服务。
