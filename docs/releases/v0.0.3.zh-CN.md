# v0.0.3：原生 DHCP 与 WebView memfd 修复

发布日期：2026-11-02。镜像：Android 13 x86_64；官方运行时：**1.1.1 / API 1**。
镜像版本与宿主运行时版本分别管理。此版本不依赖 CloudPhone、WebRTC 或 Agent。

## 相比 v0.0.2 的变化

- 提供配套 0007、0008 补丁：由 Android IpClient/DhcpClient 获取、续租和撤销租约，管理 DNS 与路由；不运行额外的宿主 DHCP 客户端。
- 统一官方配置、创建、镜像能力检查及网络状态接口。默认仍为非特权 CT、host GPU；保留静态网络和 `--no-start`，拒绝覆盖已有 VMID。
- 修复宿主 BinderFS 模块未加载时的启动失败；安装器与 pre-start Hook 复用显式宿主准备实现，并提供只读 `--check-host`。
- 增加 0009 补丁：为 memfd 添加 `F_SEAL_GROW | F_SEAL_SHRINK`，满足 WebView 156.0.8078.47 的共享内存校验；同时补充 32/64 位定向回归。
- 改进非特权 GPU 节点注入、设备权限处理，并补齐原生部署、运行接口、网络及第三方接入文档。

- 文件：`redroid13_x86_64_pve_template_v0.0.3.tar.zst`
- 大小：652,875,593 字节（约 623 MiB）
- SHA-256：`fac191efabe2390d8d0748787c6699b6df18010177fa418cb650d9f9f22dda5a`
- 内容：由已应用 0001–0009 补丁的源码构建的完整 system/vendor 镜像生成，空白 data 目录；未预装验收用 X 浏览器或测试探针。

在 PVE 宿主机执行：

```bash
cd /var/lib/vz/template/cache
wget https://github.com/hqw700/redroid-pve/releases/download/v0.0.3/redroid13_x86_64_pve_template_v0.0.3.tar.zst
wget https://github.com/hqw700/redroid-pve/releases/download/v0.0.3/redroid13_x86_64_pve_template_v0.0.3.tar.zst.sha256
sha256sum -c redroid13_x86_64_pve_template_v0.0.3.tar.zst.sha256
```

安装该标签的 `deploy/install-hooks.sh`，并检查 `pve-configure-redroid --version` 返回
`{"api": 1, "version": "1.1.1"}`。安装器会更新宿主共享命令和 Hook，运行前按开发文档备份。
创建 CT 时显式指定本版本模板，避免已有 latest 别名选择旧镜像；先查询空闲 VMID。
完整流程见[中文 README](../../README.md)与[运行接口](../runtime-api.md)。

旧镜像不会因升级宿主运行时而获得 DHCP 或 memfd 修复。此归档用于新建 CT，
不提供现有 CT 的数据迁移或自动原地升级；现有实例升级前应备份并安排停机。

## 已知限制

- 默认非特权 CT 的 GID 映射未覆盖 WebView 沙箱使用的 99000 等 GID，实测 `setresgid` 失败、页面空白。0009 修复了 memfd 校验，但未解决这一独立问题；不会自动切换特权模式或修改 ID 映射。
- 先前 1080×1920 测试出现 gralloc `SIGFPE`。本轮 720×1280 开机日志也出现过 allocator `SIGFPE`，随后恢复并完成上述检查，不能据此声明图形路径无崩溃。
- 本轮还观察到 Bluetooth 服务 abort，未验收蓝牙功能。未验证互联网浏览、完整应用功能、远程投屏与输入、其他 GPU/PVE/内核、ARM64 或其他 Android 版本。
- 默认创建分辨率仍为 1080×1920。本轮 720×1280 是显式测试配置，不代表改变默认值或证明所有分辨率可用。
