# v0.0.3: Native DHCP and WebView memfd fix

Release date: November 2, 2026. Image: Android 13 x86_64. Official runtime: **1.1.1 / API 1**.
Image and host runtime versions are independent. CloudPhone, WebRTC and an Agent are optional.

## Changes since v0.0.2

- Ship matching patches 0007 and 0008 for Android IpClient/DhcpClient lease acquisition, renewal, expiry, DNS and routing. No extra host DHCP client is used.
- Unify official configuration, creation, image capability checks and observed network status. Creation still defaults to an unprivileged CT and host GPU; static networking and `--no-start` remain available. Existing VMIDs are rejected.
- Prepare and verify host BinderFS before Android starts. The installer and pre-start Hook share host preparation logic; `--check-host` is read-only.
- Add patch 0009: seal memfd sizes with `F_SEAL_GROW | F_SEAL_SHRINK` to satisfy WebView 156.0.8078.47 shared-memory checks, with targeted 32-bit and 64-bit regressions.
- Improve GPU device injection and permissions for unprivileged CTs, and document native deployment, runtime APIs, networking and third-party integration.

## Known limitations

- Default unprivileged GID mappings do not cover sandbox GIDs such as 99000. WebView subprocesses fail at `setresgid` and the page stays blank. Patch 0009 fixes memfd validation, but does not fix this separate issue. No automatic privilege or ID mapping changes are made.
- Earlier 1080×1920 testing encountered gralloc `SIGFPE`. This run also recorded allocator `SIGFPE` during 720×1280 startup before recovering and completing the checks above. The graphics path is not crash-free.
- Bluetooth service aborts were also observed; Bluetooth was not accepted. Internet browsing, complete app behavior, remote display/input, other GPUs/PVE/kernel combinations, ARM64 and other Android versions were not tested.
- Creation still defaults to 1080×1920. The explicit 720×1280 test configuration neither changes that default nor establishes support for every resolution.
